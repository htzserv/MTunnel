# MTunnel 1.1.4

این نسخه اصلاح ظاهر هدر نسخه 1.1.3 است؛ منطق کنترل تداخل پورت حفظ شده است.

## نصب یا به‌روزرسانی از همین بسته

ZIP را روی سرور استخراج کنید، داخل پوشه‌ای که install.sh دارد بروید و اجرا کنید:

```bash
sudo bash install.sh --local .
```

نصب تمام اسکریپت‌ها و core مشترک باید با هم انجام شود؛ فقط فایل یک تانل را جایگزین نکنید.
گزینه `--local .` اسکریپت‌ها را از همین پوشه نصب می‌کند. این ZIP باینری موتورهای
Backhaul / Rathole / Paqet / HAProxy / Gost / Realm را شامل نمی‌شود؛ موتورهای
قبلاً نصب‌شده حفظ می‌شوند و نصب موتور جدید ممکن است اینترنت لازم داشته باشد.

## تغییرات

- قاب و رنگ‌بندی هدرهای GRE، VXLAN، Rathole، Backhaul و Paqet مشترک شده است.
- IPv4 و آدرس IPv6 سرور، اطلاعات سیستم و فقط ردیف‌های همان نوع تانل نمایش داده می‌شود.
- هدر اصلی و همه تانل‌ها از یک تابع رسم استفاده می‌کنند: خط اول عنوان، IPv4، IPv6، BBR و Porter؛ خط دوم CPU، هسته‌ها، RAM و ترافیک؛ خط سوم اطلاعات تانل. بین هر خط جداکننده وجود دارد.
- رنگ برچسب‌ها خاکستری، آدرس‌ها صورتی، Ping زرد، Loss سالم سبز، Up سفید و FWD فیروزه‌ای است؛ مطابق تصویر مرجع هدر اصلی.
- عرض هدر به اندازه محتوای آن است و بی‌جهت تا عرض ترمینال کشیده نمی‌شود. IPv6 در صفحه باریک به‌جای حذف انتهای آدرس شکسته می‌شود.
- حداکثر سه ردیف تانل، مطابق محدودیت قبلی هدر، نمایش داده می‌شود؛ فهرست کامل در بخش اطلاعات تانل است.
- بررسی پیش از اعمال فوروارد شامل سوکت‌های TCP/UDP در IPv4/IPv6، قوانین ورودی
  DNAT/REDIRECT در iptables و ip6tables و پورت خام سرور Paqet است.
- پورت متعلق به خود سرویس یا قانون همان تانل، تداخل با تانل دیگر حساب نمی‌شود.
- پورت مقصدِ سرور مقابل به‌عنوان پورت در حال شنود محلی بررسی نمی‌شود.
- تداخل پردازش با کارت عمودی Process / PID / Service نمایش داده می‌شود.
- پاسخ خالی یا n یعنی لغو؛ پاسخ y یعنی توقف همان سرویس یا ارسال TERM به همان پردازش،
  بررسی مجدد آزاد شدن پورت و سپس ادامه اعمال تنظیمات و راه‌اندازی تانل.
- توقف سرویس، همه پورت‌های آن را متوقف می‌کند؛ سرویس متوقف‌شده خودکار فعال نمی‌شود.
- SSH، پردازش‌های والد منو و PID 1 قابل توقف از این پرسش نیستند.
- اجرای غیرتعاملی/کرون هیچ پردازش دیگری را برای آزاد کردن پورت متوقف نمی‌کند.
- اگر سرویس دوباره پورت را باز کند، ادامه عملیات لغو می‌شود؛ توقف اجباری KILL وجود ندارد.
- قانون NAT پردازش قابل بستن ندارد: مالک نمایش داده می‌شود و باید فوروارد قبلی از
  بخش مالک آن حذف شود. قوانین تانل دیگر خودکار پاک نمی‌شوند.
- بررسی پورت محافظه‌کارانه است: استفاده از همان شماره پورت روی IP محلی دیگر هم
  گزارش می‌شود. قوانین nftables بومی، جدا از سازگاری iptables، پوشش داده نشده‌اند.
- خطای اعمال فوروارد به فراخواننده برگردانده می‌شود؛ پیام موفقیت مدیر فوروارد
  GRE/VXLAN پس از خطا نمایش داده نمی‌شود. ویرایش Rathole در خطای اعمال، تنظیم قبلی را برمی‌گرداند.

## تست انجام‌شده

- نحو هر ۹ فایل Bash با bash -n.
- ۳۴ بررسی کنترل‌شده برای پورت، تأیید/لغو با ترمینال، NAT، IPv6 و هدر.
- ۵ بررسی برابری چیدمان سه‌خطی و کدهای رنگ هدر اصلی و هدر تانل‌ها.
- ۱۰ بررسی اتصال توابع ماژول‌ها به کنترل پیش از اعمال و حفظ تنظیمات هنگام رد شدن.
- نصب کامل بسته در مسیر جداگانه آزمایشی و مقایسه فایل‌های نصب‌شده با بسته.

برای اجرای تست‌های کنترل‌شده:

```bash
python3 tests/test_port_guard.py
python3 tests/test_module_preflight.py
python3 tests/test_header_parity.py
```

تست واقعی ارتباط و فوروارد بین دو سرور در این محیط انجام نشده است.
